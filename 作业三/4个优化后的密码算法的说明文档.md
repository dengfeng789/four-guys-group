
# SM4-Opt

基于 AVX2 指令集优化的 SM4 分组密码软件实现，包含 CTR 和 XTS 两种工作模式。

## 实现内容

- 将 SM4 轮函数中的 S 盒代换与线性变换合并预计算为 1 KB 或 4 KB 的 T‑Box 表。
- 使用 AVX2 的 256 位向量指令 (`__m256i`) 实现 8 路并行加密，包括并行查表 (`_mm256_i32gather_epi32`)、向量异或及移位。
- 通过宏展开和寄存器变量轮转消除 Feistel 结构的字置换开销。
- 在 CTR 模式中批量生成连续计数器并向量化密钥流异或；在 XTS 模式中批量推导 GF(2^128) 的 tweak 值并以向量指令完成加解密前后的掩码操作。
- 关于GCM 模式的性能测试。GCM 的加密部分与 CTR 模式完全一致，可直接复用上述 CTR 优化；其认证部分 GHASH)基于 GF(2^128) 域乘法，独立于 SM4 加密核心，需要 PCLMULQDQ 等不同指令集进行优化，不在本项目范围内，其占用时间比例过大，而我们没有对认证部分做出优化手段，导致加速比例不是很高。

## 设计思路

以 T‑Box 查表替代运行时 S 盒与线性变换，降低计算量；利用 AVX2 单指令多数据能力一次性处理 8 个数据块，提升并行度；将工作模式的附加操作，如计数器递增、tweak 生成等批量处理，减少串行开销，最终形成一条全向量化的加密流水线。

## 编译与运行

- **环境**：支持 AVX2 的 x86‑64 处理器，GCC ≥ 4.9 或 Clang ≥ 3.5。
- **编译**：`gcc -O3 -mavx2 -o sm4_opt sm4_opt.c`
- **运行**：`./sm4_opt`

程序会自动完成正确性校验并输出 8 MB 数据下串行与优化版本的吞吐量对比。

# TWINE‑Opt

基于 64 位寄存器打包与 8‑Way ILP 并行优化的 TWINE 轻量级分组密码软件实现，支持 CTR、XTS、GCM 三种工作模式。

## 实现内容

- 将 TWINE 的 16 个 4‑bit 状态打包至单个 `uint64_t` 寄存器，用位运算完成 S 盒查表与置换 π，并通过宏全展开消除循环与分支开销。
- 采用 8 路指令级并行：使用 8 个独立寄存器同时处理 8 个分组，打破单块加密的数据依赖，填满 CPU 多发射端口与乱序执行队列。
- CTR 模式：一次性生成 8 个递增计数器块，经 8‑Way 并行加密后与明文进行 64 字节批量异或。
- XTS 模式：预计算 8 个连续的 GF(2⁶⁴) tweak 掩码，向量化输入/输出异或并送入 8‑Way 核心。
- GCM 模式：加密部分复用 8‑Way CTR；GHASH 采用预计算 H¹…H⁸ 的多块并行展开算法加速有限域乘法。

## 设计思路

利用轻量级密码状态小的特点，将全部半字节放入通用寄存器，消除内存访问；通过同时处理 8 个独立数据块，将单核内的指令级并行度最大化；工作模式中的计数器生成、tweak 推导和哈希密钥幂次预计算均批量完成，减少串行依赖，使加密流水线始终保持满载。

## 编译与运行

- **环境**：支持 C99 的 GCC/Clang，x86‑64 处理器。
- **编译**：`gcc -O3 twine_opt.c -o twine_opt`
- **运行**：`./twine_benchmark`

程序自动完成正确性校验并输出各模式在 8 MB 数据下的串行与优化版本吞吐量对比。

# AES‑Opt

基于 AES‑NI 与 8‑Way SIMD 指令级并行的 AES‑128 优化实现，覆盖 CTR、XTS、GCM 三种模式。

## 实现内容

- 使用 AES‑NI 指令（`_mm_aesenc_si128` 等）完成硬件加速的轮函数，大幅提升单块性能。
- 利用 `_mm_shuffle_epi8`（pshufb）进行高效的大小端转换，满足计数器自增等场景的字节序需求。
- 8‑Way 并行加密核心：同时处理 8 个 128‑bit 数据块，通过循环展开隐藏指令延迟，压榨 SIMD 端口吞吐。
- CTR 模式：批量生成 8 个连续计数器，并行加密后向量化异或输出。
- XTS 模式：预计算连续 tweak 掩码，用 SIMD 指令对 8 块明文/密文进行并行异或，再送入 8‑Way 核心。
- GCM 模式：加密部分直接复用 8‑Way CTR；GHASH 采用独立优化。

## 设计思路

借助 CPU 原生 AES‑NI 指令消除 S 盒与列混淆的软件开销；通过多块并行打破单块加密的依赖链，使乱序执行单元充分忙碌；模式层的计数器、tweak 和认证材料均批量计算，以流水线方式重叠执行，最大化整体吞吐。

## 编译与运行

- **环境**：支持 AES‑NI 和 AVX2 的 x86‑64 处理器。
- **编译**：`gcc -O3 -maes -msse4.1 -mavx2 aes_opt.c -o aes_opt`
- **运行**：`./aes_opt`

程序输出 CTR、XTS、GCM 的正确性验证结果及 16 MB 数据下的串行/并行吞吐率与提速比。

# GIFT‑Opt

基于 SSSE3 SIMD 查表与 8‑Way 并行展开的 GIFT‑128 轻量级分组密码优化实现，支持 CTR、XTS、GCM 模式。

## 实现内容

- 利用 `_mm_shuffle_epi8`（pshufb）将 4‑bit S 盒的查表操作并行化，一条指令处理 16 个半字节。
- 用字节重排与线性变换（`x ^= (x << 1)` 等）模拟比特级置换的扩散层，保持加解密可逆性。
- 8‑Way 并行核心：在 40 轮循环内同时计算 8 个 128‑bit 块，打破数据依赖，充分利用多发射端口。
- CTR 模式：预计算 8 个连续计数器，无依赖地送入 8‑Way 核心，批量异或输出。
- XTS 模式：预先进行 GF(2¹²⁸) 的多项式乘法生成 8 个连续 tweak，向量化掩码操作后送入并行核心。
- GCM 模式：加密部分复用高速 CTR 并行层，GHASH 独立处理。

## 设计思路

针对缺少比特级硬件置换的通用 CPU，采用 SIMD 字节查表替代位运算，降低指令数；通过同时处理 8 个块提升指令级并行度，隐藏查表与线性变换的延迟；工作模式中所有可并行的辅助运算均批量执行，使加密引擎始终保持高占用率。

## 编译与运行

- **环境**：支持 SSSE3 和 SSE2 的 x86‑64 处理器，GCC ≥ 4.9 或 Clang ≥ 3.5。
- **编译**：`gcc -O3 -mssse3 gift_opt.c -o gift_opt`
- **运行**：`./gift_opt`

程序执行正确性校验，并输出 8 MB 数据下各模式的串行与优化吞吐率对比。
